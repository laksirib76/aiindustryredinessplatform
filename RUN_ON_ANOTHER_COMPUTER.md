# Run the App on Another Computer

This guide explains how to run the AI Industry Readiness Platform on a new Windows computer after cloning the Git repository.

## What you need

Install these tools on the new computer:

- **Git**, to clone the repository.
- **Node.js**, which includes npm, to run the Next.js app.
- **Azure CLI**, if you want the Microsoft Foundry Learning Coach to work.

The dashboard can run without Foundry credentials, but requests to the Learning Coach require a valid Azure sign-in and permission to use the Foundry project and agent.

## 1. Clone the repository

Open PowerShell, choose a folder for your projects, and clone the repository:

```powershell
cd $HOME\source
git clone https://github.com/laksirib76/aiindustryredinessplatform.git
cd aiindustryredinessplatform
```

If the repository is private, sign in to GitHub or use an authorized clone method.

Make sure the changes and documents you need have been committed and pushed to GitHub. A clone only includes committed changes; it does not include uncommitted files from another computer.

## 2. Install the project dependencies

From the project folder, run:

```powershell
npm install
```

This uses `package.json` and `package-lock.json` to download the project dependencies. You do not need to copy the `node_modules` folder from the original computer.

## 3. Configure Microsoft Foundry locally

The repository contains `.env.example`, which shows the names and format of the settings the app expects. Create a new, private `.env.local` file in the project root on the new computer:

```env
FOUNDRY_PROJECT_ENDPOINT=https://<resource-name>.services.ai.azure.com/api/projects/<project-name>
FOUNDRY_AGENT_NAME=LearningCoach
```

Replace the example endpoint with the actual endpoint for your Foundry project. Set the agent name to the exact name of the existing agent in that project.

The actual values can be obtained securely from the project owner or administrator. Do not paste credentials or secret values into source code, commit `.env.local`, or send it through an insecure channel. `.env.local` is excluded from Git, so it will not be included when you clone the repository.

The Foundry project, model deployment, and prompt agent are hosted in Azure; they do not need to be copied as project files. The Azure account used on the new computer must have permission to invoke the agent.

## 4. Sign in to Azure

In PowerShell, run:

```powershell
az login
```

Complete the browser sign-in and select the correct tenant and subscription if prompted. Use an account that has the required permissions on the Foundry project.

If `az` is not recognized, install Azure CLI and open a new PowerShell window after installation. The app's server process must be able to find the Azure CLI on its `PATH`.

## 5. Start the app

In PowerShell, from the project folder, run:

```powershell
npm.cmd run dev
```

Then open <http://localhost:3000> in a browser.

`npm.cmd` runs npm without invoking the PowerShell `npm.ps1` script, which may be blocked by the local PowerShell execution policy. It does not change that policy.

## 6. Check the Learning Coach

On the dashboard, enter a learning goal and select **Get learning coach advice**. The first request may take several seconds.

If the request fails, check that:

1. `.env.local` is in the repository root and contains the correct Foundry project endpoint and exact agent name.
2. You have signed in successfully with `az login`.
3. Your Azure identity has permission to invoke the agent in that Foundry project.
4. The Foundry project and agent are available.
5. You restarted the development server after changing `.env.local` or Azure sign-in setup.

Keep access tokens and other credential details private. The browser should not be given Azure credentials; the app authenticates from its server.

## Files and folders you do not need to copy

- `node_modules` — recreated by `npm install`.
- `.next` — generated by Next.js when the app runs.
- `.env.local` — create it privately on the new computer rather than relying on Git to transfer it.
- Azure Foundry resources — remain in Azure and are accessed through the configured endpoint and agent name.
