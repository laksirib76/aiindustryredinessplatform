# Beginner's Guide to the AI Industry Readiness Platform

## What this project is

This project is a local prototype of a student dashboard for an AI industry-readiness pilot. It lets a student view example learning progress, practise evaluating an AI solution, and ask an AI Learning Coach for a suggested learning activity.

The dashboard currently uses **synthetic demo data**. It is not connected to real student records, and it is not a production university system.

## The two student user stories

A user story describes a feature from the user's point of view: “As a [user], I want [something], so that [benefit].”

### 1. View learning readiness

> As a student, I want to see my learning progress and competency areas, so I can understand what I am doing well and what I could work on next.

The dashboard displays an example readiness score, weekly progress, learning streak, evidence count, and skill areas with current scores and targets. For example, it shows skills such as Product Thinking and Ethical AI Practice.

These values are illustrative and come from the dashboard API. They are not official assessment results or real student records.

### 2. Practise evaluating an AI solution

> As a student, I want to respond to an AI evaluation challenge and receive formative feedback, so I can practise identifying user needs, risks, and evidence.

The student can submit a response to the “AI Evaluation challenge.” The app checks whether the response mentions a problem or user need, risks such as bias or privacy, and evidence such as testing or metrics. It then returns feedback to help the student improve.

This feedback is generated by simple rules in the app, not by Microsoft Foundry. The submission is not saved as an official grade or permanent record.

## What the Learning Coach does

The Learning Coach is a separate AI feature. A student enters a learning goal—for example, building confidence in AI product design—and selects **Get learning coach advice**.

The app sends the goal and a small set of synthetic competency indicators (skill names, current scores, and targets) to the server. The server asks the configured Foundry agent to suggest a practical learning activity, explain why it suits the goal, and describe a way to demonstrate progress. The recommendation is then shown on the dashboard.

The Coach is intended to provide learning guidance. It does not assign grades, change academic records, decide whether a student can progress, or have automatic access to student records.

## How the app connects to Microsoft Foundry

It helps to think of the connection as a secure chain:

1. **The dashboard** collects the student's goal and the demo skill indicators.
2. **The app's server** validates the request and keeps Azure authentication on the server side.
3. **Microsoft Foundry** receives the request for the configured project and agent.
4. **The prompt agent** uses its instructions and the model available to it to generate a recommendation.
5. **The server** returns the recommendation to the dashboard.

In this setup:

- **A Foundry project** is the Azure AI workspace the app connects to.
- **A model deployment** makes a language model available to the project.
- **A prompt agent** is an assistant configured in Foundry with a name and instructions. The app asks for this agent by name.
- **The project endpoint** is the address the server uses to reach the Foundry project.
- **Azure authentication** proves which signed-in identity is making the request. The browser does not receive the server's Azure credentials.

The application code for this request is in `app/api/v1/learning-coach/recommendations/route.ts`. The browser interaction is in `app/page.tsx`.

## Foundry and local configuration

The local server needs two settings, stored in `.env.local`:

```env
FOUNDRY_PROJECT_ENDPOINT=https://<resource-name>.services.ai.azure.com/api/projects/<project-name>
FOUNDRY_AGENT_NAME=LearningCoach
```

- `FOUNDRY_PROJECT_ENDPOINT` must be the endpoint for the correct Foundry project.
- `FOUNDRY_AGENT_NAME` must exactly match the prompt agent's name in that project.

Keep `.env.local` private. Do not commit it, publish its values, or put credentials in browser code. The checked-in `.env.example` contains placeholders to show the expected setting names and format.

### High-level Azure Foundry setup

1. Open or create the Microsoft Foundry project.
2. Make sure the project has a model deployment available.
3. Create a prompt agent in that project, such as `LearningCoach`, and give it instructions to provide advisory learning support.
4. Copy the project endpoint and the exact agent name into the local `.env.local` file.
5. Give the Azure identity you will use permission to invoke the agent in that project. The required role depends on your Azure project's access configuration; ask the project administrator if you are unsure.
6. Sign in to Azure on the computer running the app. The local app uses Azure's `DefaultAzureCredential` to find an available sign-in method.
7. Restart the development server after changing environment variables or authentication setup.

The agent's instructions should make clear that recommendations are advisory, that competency indicators are illustrative, and that the agent must not make official academic decisions.

## Running the app locally

From the project folder, start the Next.js development server:

```powershell
npm.cmd run dev
```

Then open `http://localhost:3000`.

In this Windows PowerShell environment, `npm` may be blocked by script-execution policy because it resolves to `npm.ps1`. Using `npm.cmd` starts the same npm script without changing that policy.

## Azure sign-in troubleshooting

During local testing, the Learning Coach returned an error because the running app could not find Azure credentials. Signing in with `az login` was not enough by itself: the development server had been launched before the Azure CLI install folder was available on its `PATH`.

The issue was resolved by:

1. Checking that Azure CLI had a saved sign-in and could obtain an Azure AI access token.
2. Restarting the development server with the Azure CLI folder on its `PATH`.
3. Sending a test request to the Learning Coach endpoint and confirming it returned a recommendation successfully.

If the same error occurs again, check that the Azure CLI is installed, sign in with `az login`, confirm the signed-in identity has the necessary Foundry project permission, and restart the server from an environment where the Azure CLI is discoverable. Do not paste access tokens or secret values into logs, source code, or support messages.

## Current prototype limitations

- Dashboard values and competency indicators are synthetic examples.
- The mission feedback is rule-based and does not represent an official evaluation.
- Mission submissions and Learning Coach conversations are not saved as a permanent student record by this prototype.
- The app does not yet provide production identity management, role-based authorization, or an institutional data store.
- A successful response from Foundry confirms the integration works; it does not mean the overall prototype is approved for real student data or academic decisions.
